20 · Booking to billing, step by step

Who talks to whom from the first save to the first invoice draft.

sequenceDiagram
  participant O as Operator
  participant M as Manager
  participant S as The system
  participant B as Billing engine
  O->>S: Enter the file,<br/>required fields and warnings checked
  S-->>O: Saved as Draft under the Operator's Company
  O->>S: Submit
  S-->>O: Pending, revision up by one,<br/>event written, file locked
  alt Manager approves
    M->>S: Approve
    S-->>M: Approved, event written,<br/>billing released
    S->>B: Rate the file
    B-->>S: Sell Lines, Cost Lines,<br/>Draft Invoice
    S->>S: Stage items in the bridge, if Review mode
  else Manager returns
    M->>S: Return with a note
    S-->>O: For Correction, note and image shown
    O->>S: Fix and resubmit, back to Pending
  end

Money in detail

27 · Voiding a posted Invoice

The books are never edited. A second, opposite entry cancels the first.

sequenceDiagram
  participant A as Accountant
  participant S as The system
  participant L as Ledger
  A->>S: Void the Posted Invoice
  S->>L: Write a Reversal Voucher in the open Period
  L-->>S: It mirrors the posted Vouchers
  S->>S: Mark the Invoice Void
  S->>S: Draft the next revision from the file
  S-->>A: New Draft Invoice, higher revision number
  Note over A,L: Posted data is never edited. There is no Credit Note.

28 · Posting an item, step by step

Who does what between a staged amount and a line in the books.

sequenceDiagram
  participant B as Billing flow
  participant A as Accountant
  participant S as The system
  participant R as Bridge rules
  participant L as Ledger
  B->>S: Stage items once each,<br/>status Staged
  A->>S: Open the queue and select items
  S->>R: Is each Charge Code<br/>linked to an account?
  alt Not linked
    R-->>A: Refused with the reason
  else Linked
    A->>S: Trial Post
    S->>R: Build the Journal in memory,<br/>check debits equal credits
    R-->>A: Trial Verified, nothing written
    A->>S: Post
    S->>L: Write the balanced Journal
    L-->>S: Journal reference
    S-->>A: Posted, audit record written
  end
  Note over A,L: A Closed Period refuses the entry
Ask AC-23 is the Trial Post mandatory AC-15 who may do each step

29 · Month-end close

After the close, the month's figures cannot change.

sequenceDiagram
  participant A as Accountant
  participant S as The system
  participant L as Ledger
  A->>S: Run month-end for the open Period
  S->>L: Create the closing entries
  S->>L: Mark the Period Closed
  S-->>A: Closed
  A->>S: Later, enter a Journal dated in that month
  S-->>A: Refused, the first open date is named
  Note over A,L: Reopening is done outside the system

31 · Voucher numbers for one Invoice

Each Invoice has three fixed Voucher numbers, and the system checks the Ledger before writing any of them, so running a step twice cannot double-post.

flowchart LR
  I["Invoice"] --> V1["Sales invoice<br/>Voucher number"]
  I --> V2["Receipt<br/>Voucher number"]
  I --> V3["Reversal<br/>Voucher number"]
  V1 & V2 & V3 --> C{"Checked against the Ledger<br/>before every write"}
  C -- "already written" --> N["Nothing written again"]
  C -- "not yet written" --> W["Voucher written"]
  R["How a customer payment<br/>gets a receipt is not described"] -.-> V2
