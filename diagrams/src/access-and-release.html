Sign-in, access and records

34 · Staying signed in, and signing out

A short-lived pass does the work. A longer renewal pass replaces it quietly.

sequenceDiagram
  participant U as User's browser
  participant S as The system
  U->>S: Save a file, with the short-lived pass
  alt Pass still valid
    S-->>U: Saved
  else Pass expired, renewal pass valid
    U->>S: Renew with the renewal pass
    S-->>U: A new short-lived pass
    U->>S: Save again
    S-->>U: Saved
  else Both expired or revoked
    S-->>U: Refused, sign in again
  end
  U->>S: Sign out
  S-->>U: Renewal pass revoked
  Note over U,S: Idle for too long, the browser ends the session
Ask TL-13 how long each pass lasts TL-11 the idle time

Every accepted change goes straight to the live site, one at a time.

  A["Work on a branch"] --> B["Pull request<br/>type check, build,<br/>automated checks"]

  C -- no --> A
  C -- yes --> D["Merge to main"]
  D --> E["Deployment, one at a time<br/>install, build web, build server,<br/>prune, bundle, publish"]
  E --> F["Live on the production slot"]
  F --> G["Health check and<br/>live site checked"]
  N["No stage where owners<br/>see a change first"] -.-> D
