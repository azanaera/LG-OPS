Freight files

3 · Approving a Freight File

Operation Status. A Pending file is locked for everyone. An Approved file is released to billing and locked for Operators.

stateDiagram-v2
  state "For Correction" as FC
  [*] --> Draft: Operator creates
  Draft --> Pending: Submit, required fields checked
  Pending --> Approved: Manager or Superadmin approves
  Pending --> FC: Return, note required
  FC --> Pending: Resubmit
  Approved --> [*]: released to billing
  note right of Pending
    Locked for everyone,
    including the Submitter
  end note
Gaps BO-02 a Manager can approve their own file OP-02 an Approved file can be edited and re-billed with no second approval OP-03 no way to cancel OP-12 no time limit, no deputy OP-16 nobody is told a file is waiting

6 · Air consolidation: why the master is 150, not 190

One master air waybill carries many house air waybills. The airline charges on the master's totals. The sum of the houses' own charges is higher, and that difference is part of the business.

flowchart TB
  HA["House A<br/>actual 100 kg, volume 60 kg<br/>charged on 100 kg"]
  HB["House B<br/>actual 40 kg, volume 90 kg<br/>charged on 90 kg"]
  HA & HB --> TOT["Master totals<br/>actual 140 kg, volume 150 kg"]
  TOT --> MW["MAWB Chargeable Weight = 150 kg<br/>the greater of the two totals"]
  HA & HB --> SUM["Houses added up: 100 + 90 = 190 kg<br/>NOT used for the master"]

10 · An Invoice

A posted Invoice is never edited. To correct it, the system reverses it and drafts the next revision.

stateDiagram-v2
  [*] --> Draft: reference number given
  Draft --> Issued: Issue, invoice number fixed
  Issued --> Posted: posted through the bridge
  Posted --> Void: Void creates a Reversal Voucher
  Void --> Draft: next revision drafted
  note right of Draft
    A total of zero or less
    is refused, there is
    no Credit Note
  end note
Gaps AC-06 no Credit Note AC-03 no exchange rate rule AC-05 official invoice rules AC-20 who re-issues after a re-rate

15 · Signing in

A small puzzle slows down automated guessing. Five wrong attempts in a row lock sign-in for one minute.

sequenceDiagram
  participant U as User's browser
  participant S as The system
  U->>S: Ask for a puzzle
  S-->>U: Signed puzzle with an expiry
  U->>U: Solve it in the background
  U->>S: Username, password and solved puzzle
  alt Puzzle bad, expired or already used
    S-->>U: Refused
  else Five failed attempts in a row
    S-->>U: Blocked for one minute
  else Wrong password
    S-->>U: Refused, counts as a failure
  else Correct
    S-->>U: Short-lived pass and a renewal pass
  end
  Note over U,S: Idle for too long, the browser signs the user out
Ask TL-11 idle time, password rules, what resets the count TL-13 how long a pass lasts BO-06 no self-service password reset

How to run the pack

16 · From triage to version 0.2

The order of work for QA. Decisions go into the one log within a working day of each session.

flowchart TB
  T["1 Internal triage<br/>120 min<br/>name owners, route questions"] --> P["2 Pre-read sent<br/>5 working days before<br/>Summary + Glossary"]
  P --> W1["3a Workshop<br/>Operations"] --> W2["3b Workshop<br/>Accounting"] --> W3["3c Workshop<br/>Business owner"] --> W4["3d Workshop<br/>Technical"]
  W4 --> PB["Play-back<br/>30 min<br/>read back, sign-off"]
  PB --> V["5 Engineering issues<br/>SRS and SAD v0.2"]
  W1 & W2 & W3 & W4 -. "within one working day" .-> LOG["4 Decisions written in<br/>OPEN-QUESTIONS.md"]
  LOG -.-> V
  classDef good fill:#d3ebe6,stroke:#1f7a6b,color:#0c2e29
  class V good
Why this order Operations first because the process starts with a booking. Accounting needs Operations' answers on files and consolidations. The Business owner settles what the first two could not. Technical turns the decisions into dates.

17 · One topic in a workshop

Every topic in every script follows this path. The proposed answer comes last, and only if the owner has no view.
